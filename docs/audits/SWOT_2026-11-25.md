# MemeRadar SWOT, 2026-11-25

Scope: the whole repository as of branch `claude/exciting-brahmagupta-0k7pds`. Evidence comes from this session's runs: `make verify`, the PostgreSQL integration suite, the 45-launch mainnet pilot, and a code review of the reverse-wallet modules. This document makes no performance claims beyond those runs.

## Strengths

- **Fail-closed safety core.**
  - The four protected modes are enforced and checked by `scripts/security_review.py`.
  - Hard-block precedence has a fixture suite (G2).
  - UNKNOWN evidence never counts as safe.
- **Verified protocol identity.**
  - Pump.fun and PumpSwap events are decoded only in their own program's execution context.
  - Discriminators are pinned to an IDL revision and sha.
  - Swaps are reconciled against balance deltas, so a token receipt is never inferred to be a buy. The pilot had 98.97% of 3,018 swaps `MATCHED`.
- **Lookahead discipline.**
  - Wallet profiles as of T use only events up to T and outcomes whose horizon has closed.
  - Outcomes are censored when post-migration trades were not decoded.
- **Operational base.**
  - Outbox-based Telegram delivery.
  - Idempotent observations with deterministic UUIDs.
  - Isolated PostgreSQL integration (35/35).
  - `make verify` covers about 1,870 backend tests and 94 frontend tests, plus SBOM and secret scans.
- **Manual workflow.** Lifecycle and revival watch, the manual exit advisor, and the Telegram `/bought`, `/sold` and `/positions` commands. None of these execute trades.

## Weaknesses

- **No proven edge.** In the pilot, copying the first non-creator buyer averaged 0.894x, a random baseline 0.759x and momentum 0.532x. No wallet qualified as a smart-money candidate. Wallet features stay in shadow mode (`WALLET_INTELLIGENCE_SCORING_ENABLED=false`).
- **Small, immature sample.** There is one 45-launch cohort; its 24h, 7d and 30d outcomes mature through 2026-12-25.
- **Public-RPC dependence.**
  - History collection and funding lookups are rate-limited and slow.
  - The funding graph covers only the first-transaction window and is `PARTIAL` for active wallets.
- **Coverage is unknown.** The completeness of the observable launch universe and subscriptions is still `UNKNOWN`, which `STATUS.md` lists as an open P0.
- **Fixed assumptions.** The fee assumption (125 bps) and the copy-latency assumptions are not calibrated against real fills.

## Opportunities

- **Turn on daily collection** (`WALLET_RESEARCH_ENABLED=true`) on the operator host. This builds 30 or more cohorts, which is the only route to measured wallet precision.
- **Promote risk-only wallet evidence first.** Manipulation, insider and funding-cluster flags can demote alerts to CAUTION before any positive wallet signal is trusted. The asymmetric downside of memecoins rewards avoiding rugs more than chasing smart money.
- **Keyed history provider.** A keyed provider (Helius or Bitquery) behind the existing port would replace slow RPC crawling. Add it only after measuring the coverage gain.
- **Copyability page.** Backtest reports are still research artifacts only; a dashboard page would expose them.

## Threats

- **Protocol drift.** Pump.fun and PumpSwap IDL changes would break decoding. `scripts/pump_idl_drift.py` detects drift, but it has to be run.
- **Adversarial wallets.** Bundled launches, wash trading, and funders made to look like exchange hot wallets. Shared-funder clusters can produce both false positives and false negatives.
- **Survivorship and selection bias.** Studying winners only would invent signals. The daily worker deliberately samples every 24–48 h launch regardless of outcome.
- **Operator risk.** The manual entries the alerts imply can still lose. The risk gates and exit advisor are advisory, and position sizing stays the operator's responsibility.

## Bugs found and fixed in this review

| Bug | Effect | Fix |
|---|---|---|
| `WalletResearchWorker._due_launches` read the first 5,000 Pump.fun `chain.event` rows of the 24–48 h window and then filtered for creates in Python | That window holds far more trades than the row cap, so launches later in the window were skipped and aged out unresearched | Filter `event_type IN ('create','create_v2')` in SQL |
| PumpSwap reconciliation compared each swap with a running partial sum | Two swaps by one user in one transaction were falsely marked `MISMATCH` | Aggregate per user first, then reconcile, the same way as curve trades |
| `shared_funder_clusters` clustered any 3–50 wallets with a common funder | A CEX hot wallet funding unrelated retail buyers was flagged as a manipulation cluster | A cluster now also needs at least 3 of those wallets to be early buyers of the same mint |
| One token's history failure aborted the whole research run | Nothing was stored for any token in that cycle | Errors are caught per token and counted as `history_failures`; the token is retried next cycle |

Tests: `tests/unit/test_pump_swap_events.py::test_two_swaps_by_one_user_reconcile_against_the_total_delta` and `tests/unit/test_wallet_funding.py::test_shared_funder_needs_a_common_early_buy_when_mints_are_known`.
